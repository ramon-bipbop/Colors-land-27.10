# План MVP и запуска

> Обновление направления от 23 октября 2026: пользователь подтвердил, что бот разрабатывается Ваней. Дальше не развиваем отдельный боевой бот параллельно: готовим интерфейс Mini App и инструкции поверх его backend. Актуальные границы и этапы — в [MINI_APP_SCOPE.md](MINI_APP_SCOPE.md). Ниже сохранён первоначальный план автономного демо, а не новый план внедрения.

## Основания

Прямое требование в прежнем чате: Telegram-бот, ручной акцепт оплаты до выдачи, учёт срока, уведомления клиенту и команде для ручного отключения, масштабируемый код. Новый ответ основателя: название условное; все коммерческие решения пустые и редактируемые; VPN существует, Telegram-бот ещё не создан.

GTM: короткий путь подключения, инструкции под iOS/Android/Windows/macOS, ручной выбор локации в VPN-клиенте, сохранение доступа при продлении, поддержка. Прежние числовые ориентиры не превращены в утверждённые тарифы.

## Выполнено в этой итерации

1. Прочитаны доступные материалы и прежний чат с требованиями. Найден точный референс @Kovalenkovpn_bot.
2. Написаны изолированные демо и боевая конфигурация без заполнения бизнес-условий.
3. Реализован цикл заказ → подтверждённый Stars-платёж → ручное одобрение → ручная выдача ссылки → продление → напоминание/задача отключения.
4. Реализованы хранение состояния, аудит, outbox, защита от повторного продления и проверка административных прав.
5. Сделан локальный кабинет и админка, проверен путь через браузер. Подготовлена инструкция запуска.

## До пилота

| Шаг | Кто / что требуется | Критерий готовности |
|---|---|---|
| 1. Условия | Основатель заполняет название, тарифы, лимиты, сроки, поддержку и тексты | check.js проходит; демо-значений нет в боевых условиях |
| 2. Бот | Основатель создаёт бота в BotFather и локально задаёт токен и admin IDs | getMe/polling успешны; администраторы получают личные уведомления |
| 3. Панель | Подтвердить панель, рабочий VPN-клиент и выдачу персональной подписки | Отдельный тестовый VPN-пользователь подключается на нужных ОС |
| 4. Платежи | Утвердить Stars и политику возврата | Реальная покупка и возврат проверены на тестовой сумме |
| 5. Сквозная проверка | Команда проходит оплату, выдачу, продление, отказ, срок и отключение | Есть подтверждение реального подключения и отключения в панели |
| 6. Постоянный процесс | VPS с Node.js 24, автоперезапуск, закрытая админка, копии | Перезапуск сохраняет данные; восстановление из копии проверено |

Домена для первого polling-бота не требуется. Публичная инструкция и Mini App — отдельные этапы после работающего бота.

## Следующие итерации

1. **API панели:** согласовать фактическую панель и версию; реализовать провижининг с сохранением panel user ID, безопасным повтором и сверкой после таймаута. Ручной акцепт оставить переключаемой бизнес-стадией, пока он нужен команде.
2. **Масштабирование:** PostgreSQL, миграции, репозитории данных, отдельные очереди и фоновые workers; тест конкурирующих одобрений. До этого только один экземпляр.
3. **Mini App:** HTTPS-домен, серверная проверка initData с проверкой возраста, пользовательские API по Telegram ID, обновление статусов и Telegram openInvoice. Текущая веб-админка не является Mini App.
4. **Операции:** индивидуальные роли, история обращений, мониторинг зависших выдач, защищённый просмотр очереди payment_incidents, инструмент сверки возвратов.
5. **Сравнение с K-VPN:** открыть доступные меню в рабочей Telegram-сессии, зафиксировать экраны и отличия. Пока нельзя обещать полное совпадение.

## Самопроверка плана

- Оплата не равна выдаче доступа: эти стадии разделены.
- Неоплата следующего заказа не отключает текущую подписку.
- Задержка проверки не удаляет уже оплаченный заказ.
- Продление и повтор события не увеличивают срок дважды.
- Смена тарифа не меняет стоимость уже выставленного заказа.
- Отказ после оплаты создаёт обязательство возврата.
- Ручное отключение обозначено как действие команды, а не автоматическая функция бота.
- Коммерческие значения пустые; тестовые значения отделены.
- Демо не использует реальные токены и VPN, не выдаётся за продакшен.
- Публичный запуск зависит от реальной интеграционной проверки; обещание «осталось два клика» пока не дано.
