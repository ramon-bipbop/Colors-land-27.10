# Запуск и подготовка размещения

## Локальный просмотр

Node.js 24+; команды выполняются из корня репозитория:

```sh
node --version
npm run demo
```

Установка npm-пакетов, домен, BOT_TOKEN, API-панель и `.env` для демо не нужны. Первый запуск создаёт `data/demo/`, копирует `config/demo.json` в `data/demo/settings.json` и создаёт SQLite. Эти файлы исключены из Git.

Главная: `http://127.0.0.1:8787/`. Админка: `/admin`. Не путать старое визуальное оформление админки с текущей главной. Процесс должен работать, компьютер — не спать. После перезагрузки компьютера локальный сервер нужно запускать снова.

Windows: `start-demo.cmd`. Для другого порта:

```powershell
$env:PORT = '8788'
npm run demo
```

Linux/macOS:

```sh
PORT=8788 npm run demo
```

Если порт занят, сначала убедиться, что это нужный экземпляр приложения, затем остановить его в исходном терминале либо выбрать другой порт. Не завершать все процессы Node.

## Как редактировать

- `public/portal-model.js`: RUB-цены, месяцы, базовый лимит, подсказки, ссылки Incy. После изменения **перезапустить Node**, так как модуль импортируется сервером.
- `public/portal.js`, `account-ui.js`, `portal.css`: интерфейс. Достаточно обновить страницу после сохранения.
- `public/connection-content.js`: отдельная инструкция. В тексте есть акция до 31 октября 2026, её нужно своевременно заменить.
- Реквизиты: `/admin` → «Настройки». Их значения хранятся в локальной SQLite. Для чистого первого запуска используется пустой `config/manual-payment.json`.

## Non-demo режим сейчас

`npm start` загружает `.env`, если он существует. Это первоначальная точка входа прототипа, **не готовая production-сборка сайта**. Она требует `ADMIN_IDS` и `ADMIN_TOKEN` длиной от 32 символов. `config/settings.json` остаётся незаполненным и не означает утверждённые настройки действующего бота.

Для просмотра demо `.env` создавать не нужно. Для OIDC настройки берутся из существующего бота по [инструкции](../TELEGRAM_LOGIN_SETUP.md). `BOT_TOKEN` оставить пустым: при его наличии в non-demo запускается старый polling-адаптер и он может конфликтовать с уже работающим ботом Вани.

Один общий bearer-токен пока даёт web-admin-доступ; реальная личность администратора не устанавливается, в аудит пишется первый `ADMIN_IDS`. Это должно быть заменено production-сессиями/ролями.

## Что учесть при размещении

1. Сначала подключить backend и проверить реальные пользовательские/администраторские сессии. Не выносить `--demo` на публичный IP или reverse proxy.
2. Текущий `HOST` — только `127.0.0.1`. Код отвергает `0.0.0.0`. Обычный Docker bridge с публикацией порта без изменений работать не будет; выбрать и реализовать нужную сетевую схему.
3. HTTPS нужен для Telegram OIDC Secure-cookie и адреса возврата. Публичный Host в сервере сейчас разрешается только при полностью включённом OIDC; `PUBLIC_ORIGIN` без client ID/secret недостаточно. Перед деплоем выделить независимую проверенную настройку внешнего origin/Host.
4. Все секреты — в окружении или secret store. Никаких API-токенов панели/бота в `public/`, Git или ответах браузеру.
5. Постоянная БД и файловое хранилище: бэкапы, восстановление, права и срок хранения чеков. Сейчас BLOB-чеков и preview-сессий автоматически не чистят. Production-очередь должна принадлежать общей БД backend Вани.
6. Ограничения reverse proxy должны учитывать чек до 10 МБ; текущий Node request timeout — 15 секунд, headers timeout — 10 секунд. Проверить поведение на медленной мобильной сети и оформить корректные HTTP-ошибки загрузки.
7. CSP сейчас `frame-ancestors 'none'`, `script-src 'self'`. Для Telegram Web Mini App нужно разрешённое встраивание и намеренная интеграция SDK/`initData`, сохранив защиту страницы.
8. Перезапуск процесса, healthcheck, журнал ошибок и мониторинг. Один loopback HTTP endpoint не равен круглосуточному хостингу.
9. Проверить доступ без VPN из нескольких сетей РФ: главная, вход Telegram, API кабинета, установка клиента, **первое получение и обновление подписки Incy**. Доступный сайт сам по себе не доказывает доступность subscription-домена.

Домен, VPS, reverse proxy, контейнерная сборка и production CI/CD этим репозиторием не развёрнуты. Публикация кода в GitHub не публикует сайт.

## Инструменты разработки

`npm test` использует встроенный Node test runner и не требует npm-пакетов. Для картинок нужен `sharp`, для browser QA — `playwright` и Chrome. Их можно поставить как служебные зависимости без изменения production-кода:

```sh
npm install --no-save --package-lock=false sharp playwright
```

На Windows `tools/preview-portal.cjs` можно запустить, задав `BROWSER_PATH` на установленный Chrome. Скрипт ожидает уже запущенное демо на `127.0.0.1:8787`, создаёт отдельную browser-сессию и тестовую заявку. Он не предназначен для production-сервера.
