## Автоматические проверки

Команда: `node --no-warnings --test test/*.test.js`.

Результат: **18 прошли, 0 ошибок** на Node.js v24.22.1, SQLite 3.53.4.

Проверены:

1. Пустая боевая конфигурация закрывает продажи.
2. Платёж не выдаёт доступ, админские действия требуют прав.
3. Повтор платежа, одобрения и выдачи не добавляет срок дважды.
4. Досрочное продление от конца периода, после истечения — от новой выдачи.
5. Владелец, валюта, сумма и уникальный charge ID.
6. Просроченный checkout и позднее успешное подтверждение оплаты.
7. Неоплата нового заказа не отключает действующую подписку; review не теряется.
8. Смена тарифов не меняет уже созданный заказ.
9. Истечение, задача ручного отключения и отсутствие повторных событий outbox.
10. Продление блокирует устаревшее подтверждение отключения.
11. Отказ создаёт требование возврата, а не доступ.
12. Реальное закрытие и повторное открытие SQLite сохраняет очередь и платёж.
13. Админский HTTP API требует токен; demo endpoints отсутствуют в боевом режиме; чужой Origin отклонён.
14. Telegram invoice использует XTR; pre-checkout проверяет владельца.
15. Запрос в групповой чат не раскрывает ссылку.
16. После простоя отправляется ближайшее актуальное напоминание, а не все пропущенные.
17. Кнопка одобрения Telegram проверяет user ID администратора.
18. Сбой отправки оставляет уведомление в очереди; повтор доставляет его.

Первые попытки выявили ограничения sandbox на локальные сетевые соединения и ошибку порядка уборки временной тестовой БД. Порядок закрытия БД исправлен; HTTP-тест затем выполнен вне сетевого ограничения sandbox. Итоговый прогон полностью успешен.

## Перепроверка реализации

Исправлены: пакет пропущенных напоминаний после простоя; потенциальная блокировка очереди неожиданным successful_payment; форматирование дат в московском часовом поясе; кнопка ручного одобрения в Telegram.

Уведомления сохраняются транзакционно вместе с бизнес-событиями. Непредвиденная оплаченная транзакция сохраняется в payment_incidents и требует ручной сверки. Доставка сообщения при сетевой неопределённости может повториться; увеличение подписки от повторного события защищено.

## Не проверено и не заявляется готовым

- Настоящие платежи Telegram, возвраты, доставка сообщений конкретным администраторам: своего бота и токена ещё нет. Bot API в тестах заменён контролируемыми ответами.
- Выдача и отключение VPN через API панели: адаптера нет, работа в панели ручная.
- Подключение на физических iPhone/Android/Windows/macOS: не проверено; клиентские инструкции требуется заполнить и проверить.
- Внутренние экраны K-VPN: доступ прочитать их через инструменты отсутствовал. Полное копирование не подтверждено.
- Mini App, публичный домен, HTTPS, многосерверная нагрузка, PostgreSQL и автоматический провижининг: последующие этапы.

Это проверка автономного MVP и демо. Публичный коммерческий запуск требует интеграционного прогона из README.
