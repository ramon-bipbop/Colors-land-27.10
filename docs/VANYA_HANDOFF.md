# Передача Ване — Colors VPN

Состояние на 27 октября 2026. Репозиторий собран для продолжения работы над сайтом и подключения к твоей существующей системе VPN/Telegram. Нового рабочего бота создавать не нужно.

## Сначала посмотреть

1. Запустить `npm run demo` на Node.js 24+ из корня репозитория.
2. Открыть `http://127.0.0.1:8787/` — это **актуальный сайт**.
3. Выбрать 3 месяца, прикрепить тестовый PNG/JPG/WebP/PDF и отправить на проверку.
4. Открыть `/admin`, найти «Чеки с сайта», скачать файл и подтвердить либо отклонить с причиной.
5. Вернуться на страницу оплаты: по подтверждению появится **фиктивная** ссылка. В кабинете попробовать «3 разных типа» и «2 телефона».
6. В `/admin` → «Настройки» есть отдельная форма реквизитов. По умолчанию поля пустые. В демо не переводить деньги и не использовать настоящие чеки.

Подробная карта: [PROJECT_MAP.md](PROJECT_MAP.md). Текущие маршруты и предлагаемые точки подключения: [INTEGRATION.md](INTEGRATION.md).

## Что утверждено владельцем

| Период | Цена за весь период |
| --- | ---: |
| 1 месяц | 250 ₽ |
| 3 месяца | 550 ₽ |
| 6 месяцев | 990 ₽ |
| 12 месяцев | 1 850 ₽ |

Базовая подписка — **3 устройства**. Рекомендация сервиса: 1 телефон, 1 компьютер и 1 телевизор. Несколько устройств одного типа показывают подсказку и отметки «Дубль типа»; это не автоматический запрет подключения.

Счётчик устройств — число зарегистрированных HWID, а не активных соединений. Если до конца подписки больше календарного месяца, кабинет показывает годы/месяцы/дни; короткий остаток — днями. Используется московский часовой пояс.

Оформление: фон `#101316`, белый знак `#F3F5F4`, зелёный `#C4F46C`, верхняя правая секция знака зелёная. Название **Colors VPN**. Предпросмотр размещён под «COLORS VPN / ВАШЕ ПОДКЛЮЧЕНИЕ». Полноэкранный вариант Telegram-входа сохранён как история; в текущем дизайне — небольшое окно входа. `/account` сейчас использует тот же flow и может показывать шаги: требование отдельного кабинета без первых шагов нужно завершить в следующей итерации, а не считать уже реализованным.

## Где подключать твою систему

1. **Единая идентичность.** Проверенный Telegram ID → существующий customer → сохранённый Remnawave user ID. Не искать клиента по username и не принимать panel ID из браузера.
2. **Чтение кабинета.** В `server.js` заменить production-заглушку `GET /api/portal/session` на обращение к твоему backend. Договориться о типах, статусах, сроках и недоступности панели; UI уже умеет показывать неизвестный счётчик без подмены нулём.
3. **Общая очередь.** Заявки сайта и бота должны храниться в одной системе. Перенести механизм снимка тарифа/проверки чека в неё; `portal_demo_sessions` и владелец по preview-cookie не подходят как production customer ID.
4. **Ручное одобрение.** Подтверждение банковского поступления, решение о выдаче и успешное изменение Remnawave — отдельные факты. При ошибке панели оставлять задачу к повтору, не повторять оплату и не продлевать доступ дважды.
5. **Mini App.** Добавить серверную проверку сырого `initData`, свежести `auth_date` и создание той же пользовательской сессии. Пересмотреть CSP под разрешённое встраивание Telegram Web; не ослаблять её до `*`.
6. **Production-администраторы.** Отдельные проверенные сессии и реальные роли/ID вместо одного общего bearer-токена. У текущего web-аудита actor всегда первый `ADMIN_IDS`, а не конкретный пользователь админки.
7. **Запуск.** Выбрать HTTPS-домен и инфраструктуру, подготовить документы/платёжный процесс, затем проверить полный путь без VPN, включая домен, с которого Incy получает первую подписку.

## Ограничения, которые важно знать до деплоя

- **Не публиковать `--demo` в интернете.** В нём админка, скачивание чеков и настройки доступны без production-токена. Локальная привязка к loopback — сознательная граница демонстрации.
- `HOST` допускает только `127.0.0.1`; обычный Docker port mapping без адаптации не сделает приложение доступным снаружи.
- Проверка публичного Host сейчас связана с полностью включённым OIDC. Одного `PUBLIC_ORIGIN` недостаточно, если нет client ID/secret. Это нужно отделить при production-интеграции.
- При `BOT_TOKEN` в non-demo `main.js` запускает старый polling-адаптер. **Оставить переменную пустой**, чтобы не создать второго потребителя обновлений существующего бота.
- Настоящий OIDC-вход в текущем сервере даёт аккаунт, но возвращает `subscription:null`, `payment:null`, `subscriptionReady:false`, `paymentReady:false` — это ожидаемая заглушка.
- Скоуп OIDC — `openid profile`: он сам по себе не выдаёт разрешение на сообщения бота и не делает пользователя администратором.
- В демо owner чеков — hash cookie браузера. Очистка cookie/другой браузер/истечение 7 дней теряют клиентскую связь с историей. `demo/logout` сохраняет историю и текущую pending-заявку этого owner.
- Автоматической очистки старых preview-сессий и BLOB-чеков нет. Понадобятся политика хранения, доступы, удаление и резервные копии.
- Совместимость reader с установленной версией Remnawave ещё не проверялась. В частности, тип ID и формат HWID-ответа нужно подтвердить.
- Компенсация до **31 октября 2026** осталась в отдельной карточке `/connect`. Текст не продлевает подписки в панели; после акции его нужно изменить.

## Чего нет в передаче

Токенов, паролей, `.env`, локальной БД, реквизитов из локальной админки, файлов загруженных чеков и данных реальных клиентов. Они не нужны для просмотра и тестов. Действующий репозиторий твоего бота не менялся.
