# Colors VPN: сайт, кабинет и интеграция

> Актуальное предложение по индивидуальным условиям, общей админке и публикации: [LAUNCH_AND_CUSTOM_TERMS.md](LAUNCH_AND_CUSTOM_TERMS.md). Старые упоминания обязательного email OTP ниже не утверждены: основной выбранный вход — Telegram.


> Актуализация: личный кабинет вынесен в `/account`, вход изменён на Telegram Login / OIDC. Подготовлен серверный код авторизации; email-OTP больше не является текущим сценарием. Настройка и оставшиеся условия — в [TELEGRAM_LOGIN_SETUP.md](TELEGRAM_LOGIN_SETUP.md). Оферта вынесена в `/offer`, полный текст ещё не предоставлен.

## Что изменилось

Главная страница `/` теперь пользовательский сайт: тарифы → оплата → подключение → кабинет. Прежняя демонстрационная админка перенесена в `/admin`. Отдельная карточка инструкции сохранена в `/connect`.

Название проекта: Colors VPN. Логотип перерисован в SVG по приложенному референсу: верхняя правая секция #c4f46c, остальные четыре #f3f5f4. Он не зависит от внешнего хранилища картинок.

Цены за полный период: 1 месяц — 299 ₽; 3 месяца — 699 ₽; 6 месяцев — 1 300 ₽; 12 месяцев — 2 440 ₽. Это рублёвые цены сайта; они не преобразованы в стоимость Telegram Stars. Доступ — на два устройства.

## Что работает сейчас

- Мобильная и настольная версии, четыре этапа, выбор тарифа, справка.
- Изолированные cookie-сессии демо и повторный переход сразу в кабинет в том же браузере.
- Тестовая персональная ссылка и копирование; три ссылки скачивания Incy, пять шагов настройки.
- Остаток подписки: до одного календарного месяца включительно — дни, свыше — годы / месяцы / дни; точная календарная дата окончания указана отдельно. Расчёт по московскому времени, с ограничением последнего дня месяца и поддержкой високосного года.
- Число зарегистрированных устройств из лимита. Это не индикатор количества одновременных VPN-соединений.
- Состояния истечения и продления, тестовые сценарии короткой/длинной подписки, заполненного лимита и привязки Telegram.
- Read-only модуль `src/remnawave-reader.js`: чтение пользователя и HWID-устройств через сервер. При ошибке получения устройств возвращается неизвестное значение, а не ложный ноль. Полный ответ панели, протокольные пароли и raw HWID не передаются в интерфейс.
- Модуль `src/account-links.js`: одноразовые ссылки со сроком 5 минут, хеширование токена, подтверждение ботом и исходной веб-сессией, защита от повтора и привязки занятого Telegram ID. Это заготовка для backend Вани, не публичный обработчик авторизации.

## Что ещё не подключено

Реальные пользователи, email-коды, платежи, Remnawave и бот. Демо не создаёт VPN-клиентов и не принимает деньги. Данные портала сейчас находятся в памяти отдельно от старой демонстрационной БД; после перезапуска процесса демо-сессии исчезают.

В боевом режиме `/api/portal/session` возвращает подтверждённый Telegram-аккаунт либо null, но без данных подписки до подключения backend. Демонстрационные изменения подписок закрыты. Никакого режима, в котором браузер может сам объявить себя пользователем Remnawave, нет. `RemnawaveReader` пока не вызывается из публичных маршрутов.

## Пользователь впервые зашёл с сайта

Этот раздел описывает первоначальный вариант email + привязка и оставлен как история обсуждения. Текущий вход — сразу через Telegram Login, без отдельной email-регистрации; кабинет доступен по `/account`. Если Telegram недоступен, общие тарифы и инструкции остаются доступны, но первичный вход через Telegram требует доступности его авторизации.

1. Посетитель смотрит предложение и выбирает тариф без Telegram.
2. Перед оплатой создаёт аккаунт сайта по подтверждённому email-коду. Email-провайдер ещё выбирается; в демо настоящий адрес не запрашивается и письма не отправляются.
3. Заказ и подписка закрепляются за внутренним `account_id`, не за Telegram username.
4. Backend подтверждает оплату, администратор одобряет выдачу в согласованном ручном процессе. Выдаётся персональная subscription URL. Веб-интерфейс показывает стадии, но не принимает решение о платеже.
5. Пользователь копирует ссылку и подключает Incy; Telegram для этого не обязателен.
6. Когда удобно, пользователь нажимает «Связать с Telegram». Сайт создаёт одноразовую ссылку вида `https://t.me/<bot>?start=link_<random_token>`; бот подтверждает Telegram ID из доверенного update. Веб-сессия затем показывает найденный аккаунт и запрашивает окончательное подтверждение.
7. В общем backend сохраняется связь `account_id ↔ telegram_id ↔ remnawave_user_id`. Одна подписка используется и на сайте, и в боте.

Нельзя связывать аккаунт только по введённому username. Нельзя объединять существующие платные аккаунты автоматически при конфликте: требуется подтверждение владения и сверка. Для входа в Mini App сервер проверяет Telegram initData и связывает проверенный Telegram ID с тем же account_id.

`AccountLinks` необходимо перенести в транзакционное хранилище общего backend, добавить уникальность Telegram ID и account ID, rate limits, аудит, безопасные cookie и CSRF-проверки. Вызов `stageFromVerifiedBot` доступен только доверенному обработчику бота, не браузеру. Статический токен, проверенный клиентом, не заменяет авторизацию.

## Источник данных Remnawave

Поток: браузер → авторизованный backend Вани → сохранённый panel user ID → Remnawave. API token панели хранится только на сервере.

Read-only адаптер использует `GET /api/users/{userId}` и `GET /api/hwid/devices/{userId}`. Читаются `status`, `expireAt`, `subscriptionUrl`, `hwidDeviceLimit` и сведения зарегистрированных устройств. Эндпоинты, идентификаторы и формат ответа нужно проверить на установленной версии: в v3 числовой user ID заменил UUID пользователя. Самостоятельного поиска по недоверенному email/Telegram ID из браузера нет.

Из пользовательского API возвращается ограниченная модель:

```json
{
  "account": {"id": "internal-id", "telegram": null},
  "subscription": {
    "status": "ACTIVE",
    "expiresAt": "2027-01-23T12:00:00.000Z",
    "devicesUsed": 1,
    "deviceLimit": 2,
    "devices": [{"name": "iPhone", "platform": "iOS", "registered": true}],
    "subscriptionUrl": "<секретная ссылка только владельцу>",
    "syncedAt": "2026-10-23T12:00:00.000Z"
  }
}
```

`deviceLimit: 2` должен реально применяться в панели. Отрисовка двух слотов сама по себе ничего не ограничивает. HWID-учёт нужно проверить с Incy на реальных устройствах. Свежесть данных — чтение при входе/обновлении кабинета, затем обновления по необходимости; для нагрузки возможен короткий серверный кеш с указанием времени обновления и инвалидированием по вебхукам. Кеш и live-polling в текущем прототипе не подключены.

## Оплата, этап 2

Предложение для самостоятельного сайта: СБП/QR от согласованного платёжного провайдера → заказ → подтверждение фактического поступления → ручной акцепт выдачи. В раннем пилоте ручная сверка допустима как выбранный процесс; одного нажатия «Я оплатил» недостаточно. Понадобятся данные получателя/провайдера, возвраты и корректная сверка заказа.

Продажа цифровых услуг внутри Telegram/Mini App требует отдельного checkout на Telegram Stars по правилам Telegram. Нельзя просто встроить банковский QR в Mini App и считать вопрос решённым. Независимый веб-checkout не следует автоматически считать исключением для покупки, начатой внутри Telegram: конкретный сценарий проверяется отдельно.

Поэтому пока этап 2 открыто показывает, что платежи не подключены, и предлагает только демонстрационный переход. Реальных реквизитов и ложного статуса «оплачено» нет.

## Доступность сайта без VPN

Сейчас весь CSS, JS, SVG и шрифты (системные) загружаются с того же хоста. Для отображения сайта не требуются Telegram API, Google Fonts, CDN или App Store. Загрузка кабинета и платежей в production также должна идти через наш backend; при отказе панели общие инструкции остаются доступны.

Это устраняет внешние зависимости, но не гарантирует доступность домена/IP в конкретных сетях. До публикации нужны:

- HTTPS-домен и хостинг, доступные целевым пользователям напрямую.
- Проверки без VPN из мобильных и домашних сетей нужных регионов: DNS, TLS, первая загрузка, вход по email, платёж, получение ссылки.
- Мониторинг извне, резервная общедоступная инструкция и процедура смены домена/узла.
- Страница должна работать и вне Telegram; Telegram привязывается позже, если сейчас недоступен.

Публичный домен и хостинг в этой итерации не назначены. Выложить страницу на любой случайный URL и обещать доступность из РФ было бы непроверенным утверждением. Текущий результат — локальный предпросмотр.

## Для интеграции, когда Ваня будет готов

1. Версия и HTTPS base URL Remnawave, серверный API token через защищённое окружение.
2. Где хранится связь аккаунта с Remnawave user ID; как обрабатываются уже существующие пользователи.
3. Username действующего бота и обработчик одноразовой привязки; секреты бота остаются у backend.
4. Почтовый сервис для OTP, правила частоты, сессии и восстановление доступа.
5. Платёжный провайдер/ручной процесс, домен и выбранный хостинг.

Код Вани в этой итерации не изменялся. Отдельный второй боевой бот не развивался.
