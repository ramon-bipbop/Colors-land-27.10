# Colors VPN: Mini App поверх бота Вани

> Уточнение: интерфейс расширен до самостоятельного сайта для первого подключения без VPN и Telegram, затем привязки к существующему боту. Реализация прототипа и текущий контракт описаны в [PORTAL_INTEGRATION.md](PORTAL_INTEGRATION.md).

Рабочий план от 23 октября 2026. Написан после чтения документа «ТЗ на МВП для Вани»: https://docs.google.com/document/d/1Z1i0fF4GqTxvIKrmiJNyKYSumfltyTjFdntTeJnR2sg/edit

## Решение о разделении работы

Не развивать второй самостоятельный бот параллельно работе Вани. Существующий локальный бот и его база — демонстрационная основа, не источник данных для будущего общего продукта. Следующая работа в этом проекте — отдельный пользовательский интерфейс Colors VPN для Telegram Mini App.

Документ содержит рабочие отметки и план, а не проверку исходного кода или production. В нём отмечены как реализованные БД/back-office, обработка ошибок, лимит устройств и отключение по сроку; аккаунт почти реализован. Основной сценарий бота и тарифы запланированы; автоматическое создание VPN-клиента после оплаты требует уточнения. Реальные API репозитория ещё не доступны для проверки.

## Границы ответственности

| Наша часть | Часть Вани |
|---|---|
| Дизайн и мобильная вёрстка Mini App | Telegram-бот и обработчики его событий |
| Инструкции и тексты | БД пользователей, заказов и подписок |
| Отображение срока и статуса | Решения о выдаче и отключении доступа |
| Копирование уже выданной персональной ссылки | Создание VPN-клиента, панель и инфраструктура |
| Отображение заявки и ожидания проверки | Подтверждение оплаты и административное одобрение |
| Тестовые сценарии и клиентский адаптер API | Авторизация запросов и реальные API |

Фронтенд не создаёт собственную боевую БД подписок, не хранит bot token и не подключается непосредственно к VPN-панели.

## Первая версия

1. **Главная / моя подписка:** статус, срок, лимит двух устройств, понятное действие «Подключить»; отдельные состояния для отсутствия подписки и истёкшего доступа.
2. **Подключение:** получение уже выданной персональной ссылки, копирование, инструкция Incy; при необходимости QR для переноса ссылки на другое устройство. QR содержит персональный секрет и не публикуется в общих материалах.
3. **Инструкции:** уже согласованная карточка и помощь по устройствам. Блок скачивания из карточки убран по решению основателя; ссылки остаются отдельным сообщением. QR и кнопки импорта — только после согласования поведения и проверки клиентов.
4. **Состояние заявки:** на проверке, одобрена/готовится доступ, доступ выдан, проблема выдачи, отказ. Оплаченная заявка не выглядит готовой, пока персонального доступа нет.
5. **Помощь:** ответы по настройке и контакт поддержки; не запрашивать приватную ссылку в публичной переписке.

Выбор локаций, управление списком устройств, самостоятельное пересоздание доступа, оплата в Mini App и рефералы не добавляются как работающие функции, пока backend их не предоставляет.

## Два этапа подключения к Telegram

**Публичная инструкция:** обычный сайт по HTTPS, открываемый из бота. Показывает общие материалы без персональной информации. Может быть готов раньше серверной интеграции.

**Персональный кабинет:** Mini App открывается из существующего бота. Backend проверяет подпись и свежесть Telegram initData, определяет пользователя и выдаёт только его данные. Нельзя доверять Telegram ID, переданному браузером самостоятельно, или одному лишь initDataUnsafe. Персональная ссылка не передаётся в URL страницы, аналитику и сторонние скрипты.

## Предлагаемый контракт интеграции — ещё не существующие API

Эти названия нужны для согласования и тестового адаптера. После доступа к коду используем существующие методы Вани, если они подходят.

- Авторизация Mini App: проверенное initData → ограниченная сессия пользователя либо проверка initData на каждом запросе.
- Чтение кабинета: состояние подписки, дата окончания в UTC, лимит устройств, состояние последней заявки и разрешённые действия.
- Чтение доступа: персональная subscription URL только владельцу и только при разрешённой выдаче. У ответов с секретом Cache-Control: no-store; состояния «доступ ещё не выдан» и ошибки различаются.
- Справочная информация: поддержка и инструкции могут быть статическими. Тарифы и оплаты подключаются отдельно после утверждения бизнес-сценария.

Для первой интеграции не обязательно менять структуру БД, переносить платежи или создавать новые VPN-пользователи из Mini App. Достаточно показать информацию и ссылку, уже сформированные существующим backend.

## Что готовим без участия Вани

- Мобильные экраны в утверждённом стиле Colors VPN.
- Тестовые ответы для всех состояний: нет доступа, заявка рассматривается, доступ готовится, активен, истёк, ошибка.
- Отдельный адаптер данных, который позже заменяется реальными HTTP-запросами.
- Корректное поведение в обычном браузере и Telegram: безопасные отступы, загрузка, ошибки, возврат назад.
- Инструкцию интеграции для Вани и перечень ожидаемых данных; сообщения ему не отправляем.

## Что потребуется при интеграции

1. Существующий bot username и доступ владельца к его настройке кнопки Mini App; новый бот не нужен.
2. HTTPS-домен/хостинг для фронтенда. Адрес localhost остаётся только локальным предпросмотром.
3. Способ проверки initData на backend и реальные методы получения статуса/ссылки.
4. Тестовый пользователь с выданным доступом и согласованный контакт поддержки.
5. Проверка на реальных Telegram iOS/Android/Desktop и подключение Incy по полученной ссылке.

## Отложенные решения

Цена, сроки тарифов и боевой платёжный сценарий остаются незаполненными. В документе желаемый QR подтверждён как намерение, а не как готовая интеграция. Для продажи цифрового доступа внутри Telegram нужно отдельно соблюдать актуальные правила Stars; оформление сайта не решает платёжную интеграцию само по себе.

Текст «Бесплатно до 31 октября» относится к согласованной информационной карточке. Источник фактического срока доступа — backend Вани; интерфейс не продлевает подписки самостоятельно. У акции должна быть дата окончания, чтобы баннер не оставался бессрочным.

## Критерий готовности

Пользователь открывает Mini App из существующего бота, видит собственный актуальный статус, получает уже разрешённый персональный доступ, копирует ссылку и подключает Incy по инструкции. Другой Telegram-пользователь получить эту ссылку не может. Срок, одобрение и отключение управляются одной системой — backend Вани.
