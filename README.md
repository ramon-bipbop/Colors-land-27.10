# Colors VPN — сайт и материалы для интеграции

Актуальная передача проекта Ване: **27 октября 2026**.

Здесь собраны пользовательский сайт, локальная админка с ручной проверкой чеков, демонстрационный сервер, подготовленный Telegram Login, reader Remnawave, тесты и исходники оформления. Код действующего бота Вани хранится отдельно; второй рабочий бот для этого проекта не требуется.

**Начать разработчику:** [Передача Ване](docs/VANYA_HANDOFF.md) → [Карта файлов](docs/PROJECT_MAP.md) → [HTTP и интеграция](docs/INTEGRATION.md).

## Запустить за несколько команд

Нужен **Node.js 24 или новее**. Для приложения и серверных тестов установка npm-пакетов не требуется.

```sh
git clone https://github.com/ramon-bipbop/Colors-land-27.10.git
cd Colors-land-27.10
npm run demo
```

Если в окружении есть Node.js, но нет команды npm, тот же запуск:

```sh
node --no-warnings src/main.js --demo
```

Открыть **http://127.0.0.1:8787/** — это актуальный сайт, который редактировали. Процесс нужно оставить запущенным. Остановка — Ctrl+C. В Windows можно вместо команды дважды открыть `start-demo.cmd`.

Не открывайте `public/index.html` как локальный файл: кабинету и загрузке чеков нужен сервер.

## Проверить основной сценарий

1. Выбрать тариф на главной.
2. Прикрепить **тестовый** чек JPG/PNG/WebP/PDF до 10 МБ и отправить на ручную проверку.
3. В `/admin` найти заявку в «Чеки с сайта» и подтвердить либо отклонить с причиной.
4. Вернуться на сайт: по подтверждению появится демонстрационная ссылка и кабинет. В кабинете есть переключатели «3 разных типа» и «2 телефона».
5. Реквизиты можно заполнить в `/admin` → «Настройки» → «Реквизиты для оплаты на сайте». По умолчанию они пустые.

Деньги не переводятся; файл чека сам по себе не подтверждает банковский платёж. В демо подтверждение создаёт только фиктивный VPN-доступ. [Подробности оплаты](MANUAL_PAYMENT.md).

## Что уже готово

- Пользовательские экраны и мобильная раскладка, календарный остаток срока, устройства и подсказка дублей.
- Локальная очередь чеков с сохранением в SQLite, снимком тарифных условий и защитой от повторного продления.
- Серверный Telegram OIDC с PKCE, state, nonce, проверкой подписи и сессиями; внешний вход ещё не проверен.
- Отдельный ограниченный reader Remnawave, пока не включённый в пользовательский API.
- Аватар, шаблоны и картинки для Telegram, исходные SVG и сохранённые варианты оформления.

## Что ещё подключать Ване

Реальную идентичность клиента, общую очередь сайта и бота, чтение/выдачу Remnawave, production-администраторов, Mini App `initData`, домен/HTTPS и реальный платёжный процесс. Сейчас production-портал возвращает аккаунт после OIDC, но не настоящую подписку; приём чеков там закрыт.

**Не публиковать режим `--demo` в интернете:** локальная админка в нём открыта без production-токена. **Не задавать `BOT_TOKEN` для существующего работающего бота:** в первоначальном адаптере это запускает отдельный polling. Все ограничения перечислены в [handoff](docs/VANYA_HANDOFF.md) и [запуске](docs/RUN_AND_DEPLOY.md).


[Подробная карта файлов](docs/PROJECT_MAP.md). Локальные `data/`, `.env`, токены, базы и загруженные чеки исключены из Git и передаваемого архива.

## Проверки

```sh
npm test
```

Эквивалент без npm: `node --no-warnings --test test/*.test.js`.

Последний подтверждённый результат — **35 тестов, все прошли**. Есть браузерный сценарий загрузки чека → ручного подтверждения → кабинета, проверки мобильной версии и дублей. Playwright/Chrome и `sharp` нужны только для служебных инструментов, обычный запуск сайта от них не зависит. [Протокол и ограничения проверки](VERIFICATION.md).

Старые цены, два устройства, email OTP и инструкции о создании нового бота из [архива](docs/history/) — история решений, а не текущие требования.
