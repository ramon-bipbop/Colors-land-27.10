# Вход в Colors VPN через Telegram

> Визуальное обновление временно откачено по просьбе основателя. Отдельный полноэкранный дизайн входа сохранён в design-versions; в текущем интерфейсе вход открывается небольшим окном. Серверные маршруты и проверки ниже сохранены. Описание отдельной страницы без шагов относится к сохранённому варианту и будет уточнено после нового ТЗ.

## Что уже написано

- Отдельная страница `/account` с экраном входа и кабинетом. На ней нет шагов выбора тарифа, оплаты и первичного подключения.
- Пункт «Оферта» ведёт на `/offer`. Финального текста нет, приём оплаты закрыт; страница сообщает, что документ готовится.
- Вход по официальному Telegram Login / OpenID Connect. Внешние Telegram-скрипты для загрузки сайта не нужны: переход к авторизации выполняется только после нажатия кнопки.
- Серверные маршруты `/auth/telegram/start` и `/auth/telegram/callback`.
- Одноразовая попытка входа, state с привязкой к исходному браузеру, PKCE S256, nonce, проверка подписи ID token по Telegram JWKS, issuer/audience/срок/время выпуска.
- Поддерживается стандартная подпись **RS256**. Другие алгоритмы из Advanced-настроек пока не включены.
- Числовой Telegram ID берётся из подтверждённого поля `id`. OIDC `sub` не используется вместо Telegram ID.
- После успеха — переход в `/account` и собственная серверная сессия в HttpOnly/Secure/SameSite cookie. Telegram ID token и OAuth access token в браузер не возвращаются и в базе не сохраняются.
- Попытки входа и хеши сессий сохраняются в SQLite; перезапуск процесса не отменяет настоящую сессию. Демо-аккаунт по-прежнему изолирован и живёт в памяти.
- При выходе серверная сессия удаляется.

## Что нужно для настоящего входа

Владелец существующего бота должен открыть BotFather → свой бот → Login Widget:

1. Добавить origin сайта, например `https://colors.example`.
2. Добавить точный адрес возврата `https://colors.example/auth/telegram/callback` в Allowed URLs.
3. Получить Client ID и Client Secret. Не присылать секреты в чат и не хранить в Git.
4. На сервере заполнить:

```dotenv
PUBLIC_ORIGIN=https://ваш-домен
TELEGRAM_CLIENT_ID=числовой_client_id
TELEGRAM_CLIENT_SECRET=секрет_из_BotFather
```

5. Оставить алгоритм Telegram Login RS256 и перезапустить процесс.
6. Настроить HTTPS reverse proxy к локальному серверу приложения. Сервер принимает явно настроенный Host из PUBLIC_ORIGIN; непроверенные forwarded-заголовки не используются для адреса возврата.
7. Пройти настоящий вход и выход на тестовом аккаунте. В текущей итерации таких реквизитов не было, поэтому внешний Telegram round-trip ещё не проверен.

Создавать второй бот не требуется. Raw BOT_TOKEN и Client Secret — разные настройки; вход использует Client Secret из раздела Login Widget.

## Что значит «код в Telegram»

Пользователь подтверждает вход в официальном интерфейсе Telegram. Если провайдер запрашивает код или пароль, они вводятся там. Colors VPN не получает пароль, одноразовый код входа в сам Telegram и доступ к личным перепискам.

Собственная форма «введите любой @username и код» не добавлена: она не доказывает владение аккаунтом. У сайта нет возможности отправить произвольному Telegram-пользователю сообщение без предусмотренного Telegram-процесса.

## Связь с подпиской

После настоящего входа `/api/portal/session` возвращает подтверждённый аккаунт, но `subscriptionReady:false`. Это намеренно: данные Remnawave ещё не связаны с backend Вани. Новому Telegram-пользователю не создаётся фиктивная действующая подписка.

Для общей системы нужно передавать проверенный `account.telegram.id` в backend Вани, находить существующего пользователя и его сохранённый Remnawave user ID, затем читать подписку через серверный адаптер. Сопоставление по username недопустимо. В демо цифры и доступ тестовые.

## Проверки

`node --no-warnings --test test/*.test.js` — **30 тестов прошли**. Проверены криптографическая подпись, неверный issuer/audience/nonce, просроченный токен, подмена payload, неподдерживаемый алгоритм, PKCE, state другого браузера, повтор callback, серверная сессия и выход.

Браузером проверены: прямой переход `/account`, отсутствие onboarding на странице кабинета и экране входа, оферта, новая цена 699 ₽, мобильная версия, возврат вошедшего пользователя и выход обратно на экран входа.

Прототипу не хватает реального HTTPS-домена, Client ID/Secret и подключённой подписки для итогового интеграционного теста. Публичный приём платежей остаётся закрытым.

Официальная документация: https://core.telegram.org/bots/telegram-login
